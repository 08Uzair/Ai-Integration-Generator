# myApp - AI Integration

A complete, self-contained AI integration for the **myApp** application at http://localhost:8100.

This project was generated by the AI Integration Generator. It gives your application an AI agent backed by real API data:

| Part | Stack | Port | Purpose |
| --- | --- | --- | --- |
| `ai-chat/AiChat.jsx` | React 18+ (drop-in, needs `react-markdown` + `lucide-react` + Tailwind) | - | Chat component you copy into **your** app |
| `ai-server/` | Node.js, Express, Groq | **4000** | Chat backend: Groq + tool calling |
| `mcp-server/` | Node.js, Express, MCP SDK | **5000** | Exposes your API as MCP tools/resources |

```
Your App (AiChat.jsx component)
    │ SSE chat stream
    ▼
ai-server (:4000)
    │ Groq Responses API            │ MCP (tools/call)
    ▼                                 ▼
   Groq                         mcp-server (:5000)
                                        │ API Adapter (env-driven)
                                        ▼
                              your API (http://localhost:8100)
```

No secrets are included anywhere in this project - all credentials are environment variables you provide.

## One-click start (Windows)

Run `.\run.ps1` from the project root. The script:

1. Creates `.env` files from the `.env.example` files (first run only - fill in your secrets afterwards)
2. Installs dependencies for both servers (`npm i` in `ai-server/` and `mcp-server/`, run `.\run.ps1 -Install` to force it)
3. Starts `mcp-server` and `ai-server` as detached processes and pumps **all their live output into one terminal** - run it from a VS Code integrated terminal to watch both services in a single window
4. Waits for both health endpoints, then keeps tailing their logs

```powershell
.\run.ps1            # install missing deps + start both servers in one terminal
.\run.ps1 -Install   # npm install for every service, then start
.\run.ps1 -Dev       # servers auto-restart on file change (--watch)
.\run.ps1 -Stop      # stop every service (also stops them on Ctrl+C)
```

> If PowerShell blocks the script with an execution-policy error, run it with
> `powershell -ExecutionPolicy Bypass -File .\run.ps1`.

## Adding the AI chat to your application

The chat is a **single component** you copy into your own app - no Next.js
project is generated anymore.

```bash
cp ai-chat/AiChat.jsx /path/to/your-app/src/components/
```

```jsx
import AiChat from './components/AiChat';

<div style={{ height: '600px' }}>
  <AiChat
    apiUrl="http://localhost:4000"
    projectName="myApp AI Assistant"
  />
</div>
```

- **Zero extra packages** - the component is plain React with its own scoped
  CSS and inline SVG icons (no Tailwind, no icon library).
- See `ai-chat/INSTALL.md` for the full setup (packages, props, user id).

### User ID (localStorage) - automatic

- The component reads the user id from `localStorage['userId']` (falls back
  to `userID` / `user_id` / `userid`) and **auto-creates one** if missing.
- It is sent with **every chat request**.
- The ai-server adds it to the AI's context and **auto-injects it into tool
  payloads** whenever a tool schema requires a user id - your API routes
  always receive it.
- Click the user chip in the header to change it (persisted instantly).

## Getting started (no Docker)

```bash
# 1. MCP server - talks to your API (the URL/port from step 1 of the wizard)
cd mcp-server
npm install
cp .env.example .env        # configure the target API below
npm run dev                 # http://localhost:5000

# 2. AI server - Groq + MCP
cd ../ai-server
npm install
cp .env.example .env        # set GROQ_API_KEY, MCP_SERVER_URL
npm run dev                 # http://localhost:4000
```

## Environment variables

| Variable | File | Purpose |
| --- | --- | --- |
| `TARGET_API_BASE_URL` | `mcp-server/.env` | Your API base URL (http://localhost:8100) |
| `TARGET_API_AUTH_TYPE` | `mcp-server/.env` | `NONE` - see auth hints below |
- No authentication is configured - the generated server calls the API without credentials
| `GROQ_API_KEY` | `ai-server/.env` | Groq key (https://console.groq.com) |
| `GROQ_MODEL` | `ai-server/.env` | Model id (openai/gpt-oss-120b) |
| `GROQ_MODEL_FALLBACK` | `ai-server/.env` | Automatic fallback when the primary model is rate-limited |
| `MCP_SERVER_URL` | `ai-server/.env` | Where the AI server reaches the MCP server |
| `CORS_ORIGINS` | `ai-server/.env` | Allowed browser origins - `*` by default (the component lives in your app) |

| `get_api_v1_user__id` | Retrieves $id from the target API via GET /api/v1/user/${id}. |
| `get_api_v1_products` | Retrieves products from the target API via GET /api/v1/products. |
| `get_api_v1_products__id` | Retrieves $id from the target API via GET /api/v1/products/${id}. |
| `create_api_v1_cart` | Creates cart from the target API via POST /api/v1/cart. Payload format: { product: string, user: string, quantity: number }. |
| `get_api_v1_cart` | Retrieves cart from the target API via GET /api/v1/cart. |
| `get_api_v1_cart__userId` | Retrieves $userId from the target API via GET /api/v1/cart/${userId}. |
| `delete_api_v1_cart__id` | Deletes $id from the target API via DELETE /api/v1/cart/${id}. |
| `delete_api_v1_cart__userId` | Deletes $userId from the target API via DELETE /api/v1/cart/${userId}. |
| `update_api_v1_cart__id` | Updates a $id from the target API via PUT /api/v1/cart/${id}. Payload format: { product: string, user: string, quantity: number }. |
| `create_api_v1_order` | Creates orders from the target API via POST /api/v1/orders. Payload format: {"product":["6689163bb32037101ed659ed","66970a1708450baa9fb9c08d"],"user":"6a7d7e2939cf8829be3874ef","quantity":2,"paymentInfo":{"id":"payment_id","status":"payment_status","paidAt":"2026-08-15T06:12:44.696Z","itemsPrice":"1899.00","taxPrice":"0","shippingPrice":"50.00","totalPrice":"1949.00"}}. |

## AI configuration

- Provider: **GROQ** (model `openai/gpt-oss-120b`, fallback `llama-3.3-70b-versatile`)
- Rate limits are handled automatically: 429 responses are retried with backoff, then the fallback model takes over.
- Add providers by implementing the interface in `ai-server/src/providers/ai-provider.js`
- Chat system prompt: `ai-server/src/services/chat.service.js`

## Customizing the generated project

Everything is plain JavaScript:

- **MCP tools** - edit `mcp-server/src/config/tools.js` (data only, no code changes needed)
- **API adapter** - `mcp-server/src/adapters/api-adapter.js` (headers, timeouts, parsing)
- **AI behavior** - `ai-server/src/services/chat.service.js` (system prompt, tool loop, user id injection)
- **Chat UI** - `ai-chat/AiChat.jsx` (single self-contained component)

## Deployment

Both servers are plain Node.js apps with Dockerfiles - deploy them to any container host (Fly.io, Railway, Render, ECS, ...). Remember to set the environment variables listed above in your platform, always including secrets.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Chat says tools unavailable | Start `mcp-server` first; check `MCP_SERVER_URL` in `ai-server/.env` |
| MCP tools return 401/403 | Check `TARGET_API_AUTH_TYPE` + credentials in `mcp-server/.env` |
| Chat error mentions GROQ_API_KEY | Set it in `ai-server/.env` |
| Chat error mentions rate limit | Automatic - retries with backoff, then falls back to `GROQ_MODEL_FALLBACK` |
| Browser can't reach AI server | Pass the right `apiUrl` prop to `<AiChat>` (localhost works when running locally) |
| Ports in use | Change `MCP_SERVER_PORT` / `AI_SERVER_PORT` in the respective `.env` files |

## Security notes

- No secrets are committed; always `cp .env.example .env` and fill values.
- MCP tool input is Zod-validated before any request reaches your API.
- The API adapter only talks to `TARGET_API_BASE_URL` - change the base URL in `.env`, never in code.
