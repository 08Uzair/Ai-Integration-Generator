## One-click start (Windows)

Run `.\run.ps1` from the project root. The script:

1. Creates `.env` files from the `.env.example` files (first run only - fill in your secrets afterwards)
2. Installs dependencies for both servers (`npm i` in `ai-server/` and `mcp-server/`, run `.\run.ps1 -Install` to force it)
3. Starts `mcp-server` and `ai-server` as detached processes and pumps **all their live output into one terminal** - run it from a VS Code integrated terminal to watch both services in a single window
4. Waits for both health endpoints, then keeps tailing their logs

```powershell
.\run.ps1            # install missing deps + start both servers in one terminal
.\run.ps1 -Install   # npm install for every service, then start
.\run.ps1 -Dev       # servers auto-restart on file change (--watch)
.\run.ps1 -Stop      # stop every service (also stops them on Ctrl+C)
```

> If PowerShell blocks the script with an execution-policy error, run it with
> `powershell -ExecutionPolicy Bypass -File .\run.ps1`.

## Adding the AI chat to your application

The chat is a **single component** you copy into your own app - no Next.js
project is generated anymore.

```bash
cp ai-chat/AiChat.jsx /path/to/your-app/src/components/
```

```jsx
import AiChat from './components/AiChat';

<div style={{ height: '600px' }}>
  <AiChat
    apiUrl="http://localhost:{{PORT_AI_SERVER}}"
    projectName="{{PROJECT_NAME}} AI Assistant"
  />
</div>
```

- **Zero extra packages** - the component is plain React with its own scoped
  CSS and inline SVG icons (no Tailwind, no icon library).
- See `ai-chat/INSTALL.md` for the full setup (packages, props, user id).

### User ID (localStorage) - automatic

- The component reads the user id from `localStorage['userId']` (falls back
  to `userID` / `user_id` / `userid`) and **auto-creates one** if missing.
- It is sent with **every chat request**.
- The ai-server adds it to the AI's context and **auto-injects it into tool
  payloads** whenever a tool schema requires a user id - your API routes
  always receive it.
- Click the user chip in the header to change it (persisted instantly).

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Chat says tools unavailable | Start `mcp-server` first; check `MCP_SERVER_URL` in `ai-server/.env` |
| MCP tools return 401/403 | Check `TARGET_API_AUTH_TYPE` + credentials in `mcp-server/.env` |
| Chat error mentions GROQ_API_KEY | Set it in `ai-server/.env` |
| Chat error mentions rate limit | Automatic - retries with backoff, then falls back to `GROQ_MODEL_FALLBACK` |
| Browser can't reach AI server | Pass the right `apiUrl` prop to `<AiChat>` (localhost works when running locally) |
| Ports in use | Change `MCP_SERVER_PORT` / `AI_SERVER_PORT` in the respective `.env` files |

## Security notes

- No secrets are committed; always `cp .env.example .env` and fill values.
- MCP tool input is Zod-validated before any request reaches your API.
- The API adapter only talks to `TARGET_API_BASE_URL` - change the base URL in `.env`, never in code.
